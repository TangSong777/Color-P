# Color-P 小狼毫：相对原版小狼毫与搜狗的定位对比

编写时间：2026-10-08
编写依据：本仓库源码、`D:\RimeUser` 实盘配置、隔离 `rime.dll` 实测，以及本次会话的审计记录
（`docs/intuition-audit-20261007.md`、`docs/switch-latency-fix-20261007.md`）。

**可信度标注**：本文凡标【实测】的，是本机跑出来的；标【代码】的是读源码得出的；标【背景】的是
关于原版小狼毫 / 搜狗的一般性背景知识，不是本会话验证的结论，请当作参考而非证据。

---

## 一、一句话定位

| | 引擎 | 候选窗 | 形态 |
|---|---|---|---|
| 原版小狼毫 | librime | Weasel 自绘（配色方案 / 皮肤） | 可自由配置的通用 Rime 前端 |
| **本定制版** | librime（同原版） | **搜狗 SSF 皮肤在 Weasel 内重绘** | 用 Rime 的引擎 + 搜狗的皮 + 一套改造过的按键交互 |
| 搜狗拼音 | 搜狗自研 | 搜狗自绘 | 商业闭源成品 |

**本质上这是一次"皮 + 交互"的移植，不是引擎移植。** 输入法内核仍是 librime 1.13.1 + `rime_ice`
方案，所以识别率、词库能力、学习行为都还是 Rime 的水平；变了的是**长什么样**和**按键怎么响应**。

## 二、相对原版小狼毫

### 2.1 增加的东西

| 方面 | 原版小狼毫 | 本定制版 |
|---|---|---|
| 候选窗渲染 | 配色方案（`preset_color_schemes`）+ 内置布局绘制 | **SSF 兼容层**：直接读搜狗的 `skin.ini` + 原图 PNG，做 9 宫格拉伸、逐像素 alpha 合成、皮肤自带字体与配色【代码：`WeaselUI/ssf/`】 |
| 皮肤资源 | Rime 自己的配色/样式 | 搜狗「竹子 Color-P」原图（27 个文件，含 `cn2.png`/`a2.png` 中英提示图） |
| 中英提示 | 文本型通知，受 `show_notifications` 控制 | **皮肤自绘的贴光标提示**，最长 2 秒（`show_notifications_time: 2000`）【实盘配置】 |
| 按键语义 | 由 schema 的 processors / key_binder 决定 | 在此之上加了 **Lua 处理器 `keypad_input`**，把物理小键盘做成"原义字面量" |
| 候选与光标 | Rime 默认 | 增加了占位 caret 检测、桌面图标区判定、多显示器负坐标兜底等宿主兼容处理【代码：`WeaselTSF/HostCompatibility.h`】 |

### 2.2 偏离原版的地方（可能让老 Rime 用户意外）

这些是**刻意的定制**，不是 bug，但从原版小狼毫迁移过来的人会不习惯：

1. **只有裸 Shift 能切中英。** 原版可通过语言栏、托盘菜单、`ascii_composer/switch_key` 多种方式切；
   本版 `RimeWithWeasel.cpp` 在 `global_ascii` + SSF 开启时**直接忽略**其他来源的 `ascii_mode`
   请求。副作用：语言栏那个「中/英」按钮点了会先假变图标、随后被纠正回来。
2. **`CapsLock` 不切中英。** 随附 `default.yaml` 注释说它应该切，但实盘
   `default.custom.yaml` 覆写成 `noop`；为它写的那段补偿代码因此是死代码。
3. **主键盘 `-` / `=` 变成翻页键。** 原版这两个键的默认行为取决于 schema；本版在
   `rime_ice.custom.yaml` 里固定映射为 `Page_Up` / `Page_Down`。有候选时它们**完全被吃掉**，
   连第一页/最后一页也不输出原字符（与 librime 语义一致，因为它在边界刻意吞键）。
4. **`Tab` 在拼音组合中被吃掉**，变成"在音节间移动光标"，切不出焦点。这是
   `rime_ice.custom.yaml` 的显式映射。
5. **`[` / `]` 回归标点。** 原版常有"用 `[` `]` 选字"的绑定，本版显式清掉了
   `select_first_character` / `select_last_character` / `import_preset`。
6. **物理小键盘完全按原义输入。** 这是最大的行为差异，见下节。

### 2.3 与原版相同、没动的地方

- 引擎、词库、方案（`rime_ice`）、学习行为、用户词典机制。
- 数字选词（顶排）、空格上屏、Enter 提交原文、方向键/Home/End 的导航语义。
- 标点体系仍是 Rime 的 `punctuator`（半角/全角两套映射）。

## 三、相对搜狗输入法

### 3.1 像搜狗的地方

- **候选窗外观**：直接复用搜狗 Color-P 皮肤的原图与 `skin.ini`，包括 9 宫格拼接、圆角/描边、
  序号与中英文各自的字体、`cn2.png`/`a2.png` 的中英切换提示。
- **中英提示的呈现方式**：贴光标的小图标 + 2 秒自动消失，这是搜狗的典型做法，而不是 Rime 原版
  的文本通知。
- **无独立状态栏**：`ssf_status_bar: false`，靠候选窗自身承载状态，与搜狗精简状态栏的风格一致。

### 3.2 和搜狗仍然不同的地方

| 方面 | 搜狗 | 本定制版 |
|---|---|---|
| 输入内核 | 自研，云端词库 + 整句模型 + 云候选 | librime + `rime_ice`（本地词库，无云） |
| 拼音容错/智能 | 强（模糊音、纠错、长句预测、云联想） | Rime 的方案能力，取决于 `rime_ice` 配置 |
| 小键盘数字 | 通常直接上屏数字（可选数字后接标点） | **按原义输入**，且拼音组合中会进入"混合输入栏"分段选词 |
| 候选交互 | 悬停高亮、点击即选、翻页箭头按下即翻 | 悬停高亮被关闭（`hover_type: none`）；点击是"按下改高亮、抬起才提交"，拖出即取消 |
| 失焦行为 | 已输入内容通常原文上屏 | **丢弃未完成组合**（`_AbortComposition`），点别处再回来那串就没了 |
| 中英切换 | 多种入口（Shift、状态栏按钮、快捷键） | **只有裸 Shift**（见 2.2） |
| 全角标点 | 完备 | 部分失效：`.` `^` `[` `$` `{` `\` `|` 输出的是全角 ASCII，而非配置的中文字符（见审计文档） |
| 鼠标/触屏 | 完整 | 基本可用，缺悬停反馈 |
| 隐私 | 有云端上传路径 | 纯本地 |

### 3.3 混合输入：本版独有的行为

这是本定制版**最不像任何一个现成输入法**的设计，值得单列：

- 物理小键盘的数字与运算符**不选词、不翻页**，而是作为字面量进入输入栏。
- 拼音与字面量可以**共存并分段选词**：例如打 `woshi` 选「我是」，再按小键盘 `4`，再打 `yang`，
  输入栏显示 `我是4yang`，此时 `yang` 仍是可选的拼音段。
- 混合态下按 `Enter` 提交**原始拼写 + 数字 + 符号**（不是提交候选）。
- 无拼音时单独按小键盘数字**不弹候选框**，直接上屏。

搜狗没有这个模式；原版 Rime 也没有。它的实际价值是给"需要频繁输入数字/符号又要打中文"的场景
（账号、型号、代码片段、带数字的口语）提供一条不切模式的通路。

## 四、当前状态：已知的实现偏差

以下都是**已确认存在、按现状保留**的（理由见 `docs/intuition-audit-20261007.md`）：

| 偏差 | 影响面 |
|---|---|
| 全角 7 个符号映射失效 | 仅主动切全角标点的用户 |
| 有候选时 `-`/`=` 完全不输出 | 想输连字符/等号的用户 |
| `Tab` 组合中被吃掉 | 想用 Tab 切焦点的用户 |
| 左右方向键在两端环绕 | 长拼音里编辑的用户 |
| 语言栏中英按钮无效（图标会假变） | 习惯点语言栏的用户 |
| 失焦丢弃未完成组合 | 所有人，偶发 |
| 拿不到光标时**原本**完全无候选窗 | 已修：现在退化为贴窗口底部的兜底位置 |
| 悬停高亮不生效 | 鼠标用户 |
| `WeaselServer.exe` 仍是 9-26 旧版 | 仅托盘/IPC 侧，不影响候选窗 |

引擎侧的深层差异（如 `navigator` 配置项需要 librime ≥ 1.16，本机是 1.13.1）属于上游版本限制，
不是本项目改出来的。

## 五、本次会话修掉的三个问题

| 问题 | 性质 | 状态 |
|---|---|---|
| 切回中文首次打字延迟 0.5–2 秒 | 本定制版引入的性能退化：切走时把整个候选面板拆掉，切回时在按键路径上重建（实测 219.6 ms → 28.6 ms） | 已修并生效 |
| 切回后候选框左上角闪一下 | 本定制版引入：新窗口创建时 caret 位置被丢掉，窗口停在屏幕原点 | 已修并生效 |
| 中文下 `123.4` 变 `123。4` | 本定制版的 Lua 处理器抢在 `punctuator` 之前提交标点，令 `digit_separators` 失效 | 已修并生效 |

前两个都是**这次移植自己带进来的**（面板生命周期与窗口重建路径），不是原版小狼毫的问题；
第三个是 Lua 处理器与 Rime 既有机制的冲突。

## 六、结论

- 相对**原版小狼毫**：引擎不变，换了一层搜狗皮，并在按键语义上做了明显改造（小键盘原义、
  只有裸 Shift 切中英、`-`/`=`` 固定翻页）。**"更漂亮的 Rime"，但不再是"标准的 Rime 手感"。**
- 相对**搜狗**：外观与中英提示的呈现方式最接近；但内核、智能度、容错、云能力差距很大，
  而且丢掉了搜狗的一些基本交互礼貌（悬停高亮、失焦保留、多入口切中英）。
- 相对**两者**：小键盘混合输入是独有的，也是这个项目最值得保留的设计。

如果要向"像搜狗一样直觉"，优先级最高的三件事是：**失焦保留已输入内容**、**语言栏/托盘中英按钮
真正生效**、**恢复悬停高亮**。这三项都不涉及引擎，只动 TSF 与 UI 层。
