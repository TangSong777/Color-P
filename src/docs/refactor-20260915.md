# Color-P core refactor, 2026-09-15

This pass covers the custom candidate-list lifecycle, mode-tip lifetime,
response handling, mixed keypad/pinyin processor, and release deployment.
It is not a claim that every upstream Weasel/Rime function has been rewritten
or that every Windows application has been exercised.

## Native candidate UI

`CCandidateList::_ShouldShowNative()` is the single policy for initial display
and popup recreation. An enabled SSF skin prefers the native Weasel window,
including hosts that request integrated candidates. Stock themes still follow
the host's request. The canonical COM identity and both candidate interfaces
remain available. Applications that prohibit third-party popups may still
control presentation; forcing visibility cannot guarantee all host behavior.

COM output strings now transfer fresh BSTR ownership to the caller. Candidate
indices and output pointers are checked, and UI-element shutdown rejects
reentrant start/end. Missing host views are handled without dereferencing null.
An IPC response failure preserves the previous complete frame instead of
publishing an empty context with an old composing flag.

## Input and notifications

Lua reads page-relative candidates without `Context:select`, because that API
fires select_notifier and may cause an early engine commit. Partial candidates
retain the unconverted pinyin. Mouse selection goes through the same virtual
commit path. For `woshi4yang5han`, intermediate choices retain converted words
and digits; the final choice commits the complete sequence. Terminal digits
are committed with the final selected word, avoiding an invisible held buffer.
Focus cancellation clears virtual input.

Mode-tip timers belong to individual popup windows and are cancelled before
destruction. A keypad digit also cancels an existing mode-tip countdown.
The session's RimeStatus member is zero-initialized instead of accidentally
initializing a shadowing local variable. Session-id generation no longer
copies every session, and app-name comparison avoids temporary allocations.

## Packaging and validation

The maintained Lua processor is `rime/lua/keypad_input.lua`. Release packages
include that file alongside x64/x86 components and a SHA-256 manifest. The
installer validates all listed files before mutation and records its completed
release and deferred replacements in deployment-status.json.

Validation: x64/Win32 Release builds; 232 SSF parser/layout/compositor checks;
32 Lua behavior assertions using a mocked Rime context and the actual processor.
The Lua fixture intentionally rejects Context:select and simulates synchronous
clear notifications. These tests do not cover actual Windows TSF host callbacks,
graphics-device loss, or the real engine's dictionary/learning integration.
To Do, Office, PixPin focus restoration and settings windows require a live
post-reboot acceptance pass. Earlier crash logs identify weasel.dll but do not
prove that a particular COM-interface change was the crash root cause.
